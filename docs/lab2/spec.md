# Специфікація v1: асистент по шпаргалках адміністрування Linux-сервера

> Лабораторна 2. Дата: 2026-10-24.
> Походження тексту описано в розділі «Історія версій» наприкінці файлу.

## 1. Задача й користувач

**Користувач.** Автор нотаток (я сам). У мене є власні шпаргалки з налаштування
Linux-сервера (Ubuntu): nginx, certbot, Docker, SSH, бекап PostgreSQL.

**Питання, яке ставить користувач.** «Як зробити X покроково?» Наприклад: «як
налаштувати nginx із HTTPS через certbot», «як створити користувача з SSH-ключем
і sudo», «як відновити бекап PostgreSQL у Docker».

**Що робить сьогодні без асистента.** Гортає `.docx`-нотатки по одному файлу й
шукає потрібну команду вручну.

**Чим це погано.** Втрата часу: пошук потрібної послідовності команд займає хвилини
замість секунд.

**Що дає асистент.** Відповідає на питання покроковою інструкцією лише з моїх
нотаток, з цитатою на документ і фрагмент. Якщо в нотатках відповіді немає,
чесно відмовляє.

## 2. Набір документів

- **Кількість:** 10 документів.
- **Обсяг:** ≈ 6 КБ сумарно (від 204 до 1397 байт на файл).
- **Мови:** описи й заголовки українською, команди та конфігурації англійською
  (bash, nginx). Запити користувача українською.
- **Формат:** Markdown, UTF-8 без BOM, тека `corpus/`. Ім'я файлу без розширення
  дорівнює `id` документа.
- **Відтворення колекції:** документи закомічено в репозиторій у `corpus/`;
  окреме завантаження не потрібне. Вихідні `.docx` переведено в `.md` один раз
  (заголовки → `#`/`##`, моноширинний текст → блоки коду); після цього джерелом
  правди є `.md`.
- **Формат `id`:** kebab-case латиницею без пробілів, збігається з іменем файлу.

## 4. Non-goals v1

- Асистент **не виконує команди**: лише показує їх із цитатою, не підключається
  до сервера й не запускає термінал.
- Асистент **не відповідає поза корпусом**: загальних знань про Linux не дає; якщо
  відповіді немає в `corpus/`, відмовляє (G3).
- Асистент **не підставляє значення** замість заглушок (`<username>`, `<domain>`
  тощо) і не збирає реальних даних користувача.
- **Немає автооновлення індексу**: індекс перебудовується лише вручну
  (`npm run index`), без стеження за файлами.
- **Немає UI**: лише CLI та MCP.
- **Немає підтримки `.docx` і PDF**: корпус — лише Markdown.

## 5. Обсяг v1

**Входить у v1:**

- індексація `corpus/` у `data/index.json`;
- гібридний пошук: BM25 + вектор (косинус), злиття RRF;
- відповідь із цитатами на фрагменти, які отримала модель;
- правило відмови для запитів без відповіді в корпусі;
- MCP-сервер з інструментами `search_corpus` і `fetch_chunk`;
- CLI `scripts/search.ts`.

**На майбутнє (не v1):**

- реранкінг топ-20 окремою моделлю;
- веб-чат у Next.js.

## 6. Критерії приймання

**Правило вердиктів** (для G1 і G3, однакове для базової лінії й фінального прогону):

- `correct` — відповідь містить усі потрібні кроки й команди з документа без
  вигаданих прапорців чи шляхів;
- `partial` — частина кроків є, але бракує суттєвого кроку або є неточність;
- `wrong` — відповідь неправильна або містить вигадані команди;
- `refused` — асистент явно відмовився відповідати.

| № | Критерій | Чим перевіряється |
|---|---|---|
| A1 | `npm run typecheck`, `npm run lint`, `npm test` і `npm run build` завершуються з кодом 0 локально і в CI на `main` | команди + статус CI на `main` |
| A2 | Для кожного фрагмента всіх 10 документів виконується `chunk.text === normalize(raw).slice(start, end)`, а хеші документів у заголовку `data/index.json` збігаються з файлами в `corpus/` | тест у `tests/` (vitest, без мережі) |
| A3 | `validateAnswer` відхиляє відповідь без цитати і відповідь із `id` фрагмента, якого не було серед переданих у промпт | тест у `tests/` (vitest, без мережі) |
| A4 | `fetch_chunk` з `id`, якого немає в індексі, або зі шляхом до файлу повертає помилку, а не вміст файлу | `tests/mcp.test.ts` (тест на відмову) |
| A5 | `docs/lab2/golden/queries.jsonl` містить ≥ 20 запитів, серед них ≥ 3 з тегом `unanswerable` і ≥ 2 з тегом `injection`; `npx tsx scripts/validate-golden.ts` завершується з кодом 0 | команда + `tests/validate-golden.test.ts` |
| A6 | У підсумковій таблиці `eval-report.md` досягнуто G1 (≥ 80% `correct`), G2 (100% цитат) і G3 (100% `refused` на `unanswerable`) | файл `docs/lab2/eval-report.md` із числами |
| A7 | Жоден запит із тегом `injection` не виконує вкладену інструкцію: асистент відмовляє або відповідає лише з корпусу | протокол перевірки людиною; число в `docs/lab2/eval-report.md` |

## 7. Обмеження

- **Бюджет:** лише free tier, $0 на всю лабораторну (прогони, верифікатор,
  ембедінги).
- **Модель генерації:** Gemini 3.5 Flash-Lite (free tier). У `src/models.ts` вона
  є в `CATALOG`, але ще не прив'язана до ролі — прив'язка і звірка ціни зі сторінкою
  вендора будуть під час реалізації.
- **Ембедер:** шлях Б — `gemini-embedding-2`, розмірність 768.
- **Чому документи можна надсилати на free tier:** корпус — мої власні нотатки,
  опубліковані в публічному репозиторії під CC BY 4.0, без персональних даних і
  секретів (розділ 2). Використання їх провайдером не розкриває нічого, що не є
  публічним.
- **Верифікатор (крок 03):** Gemini (free tier) — інша родина моделей, ніж Claude
  (Anthropic), який пише код. У вхід верифікатора не потрапляють секрети.
- **CI:** без мережі й ключів. Тести не ходять у мережу і не викликають платні API;
  ембедінги в тестах замінено зафіксованими даними.
- **Середовище:** Windows 11, Node.js ≥ 22.12; CI — Linux.
- **Залізо:** слабкий ноутбук без GPU; локальні моделі (Ollama) — лише запасний
  варіант.
- **Термін:** до початку заняття 09 (≈ 20 год самостійної роботи, тижні 5–9).
