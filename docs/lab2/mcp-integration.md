## Чим відрізняються два боки
- **Робоча тека.** Claude Code запускає сервер у теці сесії (корінь репозиторію, звідки запущено `claude`); поля
  `cwd` у `.mcp.json` Claude Code немає, тож відносний `src/mcp/server.ts` працює лише тому, що сесія стартує в
  корені. Застосунок задає `cwd` явно — корінь від `import.meta.url` скрипта. Сам сервер шляхи бере від свого
  `import.meta.url`, тому від робочої теки не залежить
- **Оточення процесу.** Застосунок передає лише `getDefaultEnvironment()` (безпечний мінімум SDK) + `MCP_CLIENT_LABEL`
  — своїх секретів серверу не віддає. Claude Code передає оточення сесії + `env` з `.mcp.json` (яке саме — не
  перевіряли). В обох випадках ключ ембедера в конфігурації **не передається**: сервер читає його сам з файлу поза
  git через `--env-file-if-exists` і без файлу працює з відмовою лише в `search_corpus`
- **Аргументи.** Агент не передав `topK` → типове 5 зі схеми; застосунок передав `topK: 3`. Обидва значення видно в
  журналі сервера вже після валідації
- **Таймаути:**

| Де | Значення | Звідки |
|---|---|---|
| Сервер, обробник | 10 000 мс (`LIMITS.timeoutMs`) | `src/mcp/tools.ts`, mcp-spec.md |
| Застосунок (`@modelcontextprotocol/client` 2.3.1), запит | 60 000 мс (`DEFAULT_REQUEST_TIMEOUT_MSEC = 6e4`) | код пакета в `node_modules` |
| Claude Code, виклик інструмента | поле `timeout` у `.mcp.json` не задано, `MCP_TOOL_TIMEOUT` не задано → типово ~28 год; для stdio окремого таймера на запит немає | https://code.claude.com/docs/en/mcp, 2026-10-26 |
| Claude Code, старт сервера | `MCP_TIMEOUT` не задано; типового значення сторінка не наводить | там само |

- Що з цього я зафіксував у `mcp-spec.md` як вимогу, а не як випадковість: (1) клієнтам — пряма команда, не
  `npm run mcp`; (2) таймаут сервера (10 с) менший за таймаути обох клієнтів, тож клієнт бачить причину відмови
  сервера, а не свою помилку; (3) шляхи в сервері — від `import.meta.url`

## Секрети
- Жодного значення ключа в закомічених конфігураціях: у `.mcp.json`, `scripts/mcp-demo.ts` і `src/mcp/*.ts` пошук
  `AIza|sk-|API_KEY|apiKey|Bearer` знаходить лише **назву** змінної в `src/mcp/server.ts:34` (перевірка, чи ключ є
  в оточенні), жодного значення
- Що файли з ключами не в індексі git — перевіряє автор (агентові це заборонено hook-ом):
  `git ls-files | grep -i env`. Результат автора 2026-10-26 на `lab2/step-09`: `.env.example`, `next-env.d.ts`
  (типи Next.js), `scripts/guard-env.mjs` (сам hook) — файлів із ключами в індексі git **немає**
- Де насправді лежать ключі: у файлі поза git у корені репозиторію (веде людина); у репозиторії — `.env.example`
  без значень
